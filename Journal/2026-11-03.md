## Тема: Построение SOAR-системы (Wazuh + Shuffle + Python + Active Response)

Сегодня мы завершили эпопею с автоматизацией реагирования. Это был день, полный ошибок, озарений и, в конце концов, полной победы. Мы построили систему, которая сама блокирует атакующих.

### 1. Проблема шторма событий и лимитов Shuffle
Начали с того, что Wazuh отправлял в Shuffle абсолютно всё (уровень 3). Это привело к двум проблемам:
*   **Лимит Shuffle Cloud:** Мы исчерпали бесплатный лимит в 2000 выполнений узлов за месяц. Shuffle перестал обрабатывать запросы.
*   **Рекурсия:** Wazuh отправлял события о работе самого Shuffle (запуск контейнеров), Shuffle их обрабатывал, генерировал новые логи, которые снова уходили в Wazuh. Замкнутый круг.
*   *Решение:* В конфиге Wazuh (`ossec.conf`) мы подняли порог `<level>` с 3 до **10**. Теперь в SOAR уходят только реальные атаки (брутфорс, DCSync и т.д.). А также перешли на локальный Open Source Shuffle, чтобы снять лимиты.

### 2. Эпопея с авторизацией в Wazuh API (Ошибка 401)
Когда цепочка Webhook ➔ HTTP ➔ Email заработала, узел HTTP упорно выдавал `401 Unauthorized: No authorization token provided`. 
*   **Попытка 1:** Вписали логин/пароль в поле Basic Auth в Shuffle. Не помогло (Shuffle игнорировал заголовок).
*   **Попытка 2:** Передали креды в URL (`https://user:pass@...`). Не помогло.
*   **Попытка 3:** Закодировали креды в Base64 и вписали вручную в Headers. Всё равно `401`.
*   *Решение:* Заменили узел HTTP на **узел Python**. В скрипте сначала отправляем POST-запрос на `/security/user/authenticate`, получаем JWT-токен, а затем с этим токеном делаем PUT-запрос на `/active-response`. Это исключило баги Shuffle.

### 3. Ошибка `Cannot read 'srcip'` в Wazuh
API Wazuh принял команду (Shuffle вернул `200 OK`), но блокировка не срабатывала. В логах `active-responses.log` было: `Cannot read 'srcip' from data or invalid IP format`.
*   **Причина:** Скрипт `firewall-drop` в Wazuh ожидает IP-адрес внутри объекта `alert.data.srcip`. Мы передавали только аргументы, а объект `alert` был пустым.
*   *Решение:* В Python-скрипте мы вручную сформировали структуру `alert`:
```json
"alert": {
  "data": {
    "srcip": "10.10.10.203"
  }
}
После этого скрипт Wazuh увидел IP.

4. Финальный триумф
Запустив брутфорс с Kali (12 попыток), мы получили:

Wazuh зафиксировал событие уровня 10 (правила 5551 и 5763).

Shuffle принял алерт.

Python-скрипт авторизовался в API, сформировал запрос и отправил команду на блокировку.

На почту пришло письмо с полными данными инцидента.

Главное: На Ubuntu появились правила iptables DROP для IP-атакующего (10.10.10.203).

### 📄 Полноценный отчет по проекту: PRJ-009 (SOAR System)

**Название проекта:** Развертывание SOAR-системы на базе Wazuh и Shuffle с автоматическим реагированием.
**ID документа:** PRJ-009
**Дата начала:** 02.11.2026
**Дата окончания:** 03.11.2026
**Исполнитель:** WISL

#### 1. Цель проекта
Создать систему, которая автоматически анализирует события безопасности (SIEM), обогащает их данными (Threat Intelligence) и выполняет ответные действия (Active Response) без участия человека.

#### 2. Используемое ПО и инструменты
*   **SIEM:** Wazuh 4.14 (Docker, single-node) на Ubuntu 22.04 (IP: 10.10.10.20).
*   **SOAR:** Shuffle (Open Source, локальная установка через Docker Compose).
*   **Атакующий:** Kali Linux (IP: 10.10.10.203).
*   **Цель:** Ubuntu 22.04 (агент Wazuh ID: 004).
*   **API:** Wazuh REST API, VirusTotal API.
*   **Уведомления:** Gmail SMTP (с использованием App Password).

#### 3. Описание среды и ресурсы
*   **Хост-система:** VirtualBox на внешнем SSD.
*   **ВМ Ubuntu:** 10 ГБ RAM, 8 CPU, 128 МБ видеопамяти.
*   **Сеть:** Внутренняя сеть `10.10.10.0/24`.
*   **Примечание:** Из-за тяжести Shuffle (12+ контейнеров) и OpenSearch, ВМ Ubuntu требовала значительных ресурсов. Была произведена оптимизация: удалены лишние реплики контейнеров Shuffle, отключен Snap Firefox в пользу Deb-версии.

#### 4. План действий (краткий)
1.  Развернуть локальный Shuffle (Docker Compose).
2.  Настроить интеграцию Wazuh ➔ Shuffle (кастомный скрипт `custom-shuffle.sh`).
3.  Настроить цепочку в Shuffle: Webhook ➔ Condition (Level > 7) ➔ VirusTotal ➔ Python (Active Response) ➔ Email.
4.  Написать Python-скрипт для авторизации в Wazuh API и отправки команды `firewall-drop`.
5.  Провести тестовую атаку (SSH Brute Force) и проверить блокировку.

#### 5. Результаты
*   Интеграция Wazuh и Shuffle работает. Алерты уровня 10 доходят до SOAR.
*   VirusTotal обогащает данные (проверка IP атакующего).
*   Python-скрипт успешно получает JWT-токен и отправляет команду Active Response.
*   Wazuh Agent выполняет скрипт `firewall-drop`, блокируя IP атакующего в `iptables`.
*   Email-уведомления приходят с полными данными инцидента.
*   **Проблемы:** Лимиты Shuffle Cloud, ошибки авторизации (401), неверный формат `alert` для `firewall-drop`. Все решены.

#### 6. Скриншоты/логи (ссылки)
*   Логи `active-responses.log` с успешным выполнением.
*   Вывод `iptables -L INPUT` с правилом DROP.
*   Скриншоты выполнения в Shuffle (зеленая цепочка).
*   Пример письма на почте.

#### 7. Выводы
Построена полноценная SOAR-система. Wazuh детектирует, Shuffle оркестрирует, Python выполняет активные действия, Gmail уведомляет. Это уровень зрелой системы безопасности, готовой к использованию в реальных SOC.

#### 8. Рекомендации
*   Добавить белый список IP-адресов в скрипт `firewall-drop`, чтобы не заблокировать себя.
*   Настроить дедупликацию уведомлений (не отправлять письмо на каждый повторный алерт).
*   Интегрировать TheHive для создания инцидентов.
