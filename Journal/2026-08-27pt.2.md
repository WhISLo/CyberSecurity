Выполненные задачи и результаты
1. SQL Injection (вход без пароля)
Уязвимость: классическая SQLi в форме входа.

Payload:

Email: ' OR 1=1--

Password: любое (например, 123)

Результат: Успешный вход под учётной записью администратора.

Объяснение: Запрос формируется как:

sql
SELECT * FROM Users WHERE email = '' OR 1=1--' AND password = '123'
Комментарий -- отключает проверку пароля, условие OR 1=1 всегда истинно.

Вывод: SQL Injection присутствует, критическая уязвимость.

2. XSS (межсайтовый скриптинг) в поиске
Уязвимость: отражаемый XSS в поле поиска.

Payload: <script>alert('XSS')</script>

Результат: При вводе в поле поиска и нажатии Enter появляется всплывающее окно с сообщением XSS.

Объяснение: Приложение не экранирует пользовательский ввод и вставляет его в HTML-код страницы без фильтрации.

Вывод: XSS присутствует, может быть использован для кражи сессий или перенаправления.

3. IDOR (Insecure Direct Object Reference)
Попытка: Доступ к профилю другого пользователя путём изменения параметра id в URL (/profile?id=1 на /profile?id=2).

Результат: Не сработало. При попытке перейти на /profile?id=2 приложение перенаправляет на страницу входа или показывает ошибку «недостаточно прав».

Причина: Вероятно, на сервере реализована проверка прав доступа: пользователь может видеть только свой профиль, даже если передаёт другой ID. Это может быть защита на уровне контроллера (например, сверка id с ID текущего пользователя в сессии).

Вывод: Уязвимость IDOR отсутствует, приложение правильно проверяет авторизацию на доступ к объектам.

4. Burp Suite – перехват и модификация запросов
Действие: Настроен перехват трафика, выполнен захват POST-запроса при логине. Модифицировано поле email на ' OR 1=1--, отправлено.

Результат: SQLi успешно сработала и через Burp, что подтверждает её наличие и позволяет автоматизировать эксплуатацию.

Отчёт по веб-пентесту OWASP Juice Shop
Дата: 27 августа 2026
Исполнитель: Маслов Владислав (WhISLo)
Цель: Провести базовый анализ защищённости веб-приложения OWASP Juice Shop, выявить и задокументировать уязвимости из OWASP Top 10.
Среда: Kali Linux (IP 10.10.10.100), OWASP Juice Shop (Docker, порт 3000), Burp Suite Community.

1. Разведка (Reconnaissance)
1.1. Robots.txt
При обращении к /robots.txt обнаружена запись:

text
User-agent: *
Disallow: /ftp
Это указывает на наличие директории /ftp, которая может содержать файлы, не предназначенные для индексации. При попытке перейти в /ftp открывается список файлов, что является потенциально опасным (Information Disclosure). Некоторые файлы доступны для скачивания (например, acquisitions.md).

1.2. Страница с отзывами
На странице товаров присутствуют отзывы пользователей. В неавторизованном состоянии отображаются только общие комментарии, email-адреса скрыты. Это говорит о том, что приложение корректно разделяет доступ для аутентифицированных и неаутентифицированных пользователей, что является хорошей практикой.

1.3. Конфигурационные файлы
При попытке обращения к /config или стандартным путям (например, /config.json) сервер возвращает ошибку 404, что свидетельствует о том, что чувствительные файлы защищены.

2. Обнаруженные уязвимости
2.1. SQL Injection (SQLi)
Описание: В форме входа (/login) обнаружена классическая SQL-инъекция, позволяющая обойти аутентификацию.
Payload:

Email: ' OR 1=1--

Password: любое (например, 123)

Результат: Успешный вход под учётной записью администратора без знания пароля.
Объяснение: Приложение формирует SQL-запрос вида:

sql
SELECT * FROM Users WHERE email = '' OR 1=1--' AND password = '123'
Комментарий -- отключает проверку пароля, условие OR 1=1 всегда истинно.
Риск: Критический – позволяет получить полный доступ к системе.
Рекомендация: Использовать параметризованные запросы (prepared statements), строгая валидация входных данных.

2.2. Межсайтовый скриптинг (XSS)
Описание: В поле поиска на главной странице обнаружен отражаемый XSS.
Payload: <img src=x onerror=alert('XSS')> или <script>alert('XSS')</script>
Результат: При вводе payload в поисковую строку и нажатии Enter выполняется JavaScript, появляется всплывающее окно.
Объяснение: Приложение не экранирует пользовательский ввод и вставляет его в HTML-код страницы без фильтрации.
Риск: Средний – может быть использован для кражи сессионных cookie, перенаправления или фишинга.
Рекомендация: Экранировать весь пользовательский вывод, использовать Content Security Policy (CSP).

2.3. Попытка эксплуатации IDOR
Описание: Проверка наличия уязвимости Insecure Direct Object Reference путём изменения параметра id в URL профиля (/profile?id=1 → /profile?id=2).
Результат: Уязвимость не подтверждена. Приложение правильно проверяет права доступа и не позволяет просматривать чужие профили, даже если изменить ID.
Риск: Отсутствует.
Рекомендация: Оставить текущую реализацию контроля доступа, она работает корректно.

2.4. Использование sqlmap (автоматизированный поиск SQLi)
Действие: Запущен sqlmap для поиска SQL-инъекций в параметрах email и password формы логина.
Результат: sqlmap не обнаружил инъекций ни в одном из параметров, несмотря на то, что ручная инъекция сработала.
Причина: Вероятно, старая версия sqlmap (1.10.2) или использование защиты на стороне сервера (например, фильтрация некоторых паттернов). Возможно, ручная инъекция сработала из-за нестандартного синтаксиса, который sqlmap не распознал.
Вывод: Автоматические инструменты не всегда заменяют ручное тестирование. Ручная проверка обязательна.

3. Дополнительные наблюдения
Файл robots.txt: Указывает на директорию /ftp, где доступны файлы, которые могут содержать конфиденциальную информацию.

Отсутствие стандартных учётных записей: Попытки входа под учётными записями по умолчанию (например, admin@juice-shop / admin123) не увенчались успехом, что говорит о том, что они либо удалены, либо изменены.

Некорректная работа sqlmap: Возможно, из-за отсутствия поддержки некоторых типов инъекций в старой версии, либо из-за специфики Node.js/базы данных SQLite.

4. Заключение
В ходе пентеста OWASP Juice Shop были успешно выявлены и подтверждены следующие уязвимости:

SQL Injection (критическая) — обход аутентификации через форму входа.

Reflected XSS (средняя) — в поле поиска.

Уязвимость IDOR не обнаружена, приложение корректно проверяет права доступа.
Сканирование sqlmap не принесло результатов, что подчёркивает важность ручного тестирования.

Рекомендации по улучшению безопасности:

Внедрить параметризованные запросы для всех SQL-операций.

Экранировать весь пользовательский ввод и вывод, добавить CSP.

Ограничить доступ к директории /ftp через конфигурацию веб-сервера или удалить её.

Регулярно обновлять инструменты тестирования (sqlmap, Burp Suite) до актуальных версий.
