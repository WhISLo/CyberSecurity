# 📅 Отчёт по проекту: Детекция AD-атак в Wazuh (Detection Engineering)

**Дата:** 21.09.2026  
**Исполнитель:** WISL  
**ID документа:** PRJ-004 (продолжение)  
**Связанные отчёты:** День 7–8 (Kerberoasting, AS-REP, secretsdump, PtH)

---

## 🎯 Цель

Завершить настройку детекций для Active Directory атак в Wazuh: подключить Windows Server к SIEM, написать и протестировать правила для Kerberoasting, DCSync и Pass-the-Hash. Провести тестирование правил без запуска реальных атак (из-за временного отсутствия VPN) с помощью встроенного инструмента `wazuh-logtest`.

---

## 🛠️ Используемое ПО и инструменты

- **SIEM:** Wazuh 4.14.0 (Ubuntu Server 22.04, IP 10.10.10.20)
- **Атакующая ВМ:** Kali Linux (10.10.10.100)
- **Целевые ВМ:** Windows Server 2022 (DC, 10.10.10.10), Windows 10 (10.10.10.201)
- **Инструменты:** `wazuh-logtest`, `systemctl`, текстовый редактор `nano`

---

## 🖥️ Описание среды

Лаборатория из 5 виртуальных машин (VirtualBox) на внешнем SSD.  
Все ВМ в сети `10.10.10.0/24`.  
Wazuh развёрнут через Docker (single-node) на Ubuntu.  
Агенты Wazuh установлены на Windows Server и Windows 10.

---

## 📋 План действий (краткий)

1. Подключить Windows Server к Wazuh (установить агент, настроить `ossec.conf`, запустить службу).
2. Написать правило Wazuh для обнаружения Kerberoasting (Event ID 4769, RC4).
3. Написать правило Wazuh для обнаружения DCSync (Event ID 4662, Replicating Directory Changes).
4. Написать правило Wazuh для обнаружения Pass-the-Hash (Event ID 4624, Logon Type 3 + NTLM).
5. Перезапустить менеджер Wazuh.
6. Протестировать правила с помощью `wazuh-logtest`, подавая симулированные логи.
7. Задокументировать результаты и обновить отчёт по AD-атакам.

---

## ✅ Результаты

### 1. Подключение Windows Server к Wazuh
- Агент Wazuh установлен на Windows Server.
- В `ossec.conf` указан manager IP: `10.10.10.20`.
- Служба `WazuhSvc` запущена.
- В дашборде Wazuh (`https://10.10.10.20`) агент WinServer отображается в статусе **Active**.

### 2. Правило для Kerberoasting (ID 100210)
Добавлено в `/var/ossec/etc/rules/local_rules.xml`:

```xml
<group name="windows,kerberoasting,">
  <rule id="100210" level="10">
    <if_sid>60106</if_sid>
    <field name="win.system.eventID">^4769$</field>
    <field name="win.eventdata.ticketEncryptionType">^0x17$</field>
    <description>Possible Kerberoasting - TGS request with RC4 encryption</description>
    <mitre>
      <id>T1558.003</id>
    </mitre>
  </rule>
</group>

### 3. Правило для DCSync (ID 100200)
<group name="windows,dcsync,">
  <rule id="100200" level="12">
    <if_sid>60106</if_sid>
    <field name="win.system.eventID">^4662$</field>
    <field name="win.eventdata.properties">Replicating Directory Changes</field>
    <description>Possible DCSync attack - Replicating Directory Changes access</description>
    <mitre>
      <id>T1003.006</id>
    </mitre>
  </rule>
</group>


### 4. Правило для Pass-the-Hash (ID 100201)
<group name="windows,pth,">
  <rule id="100201" level="10">
    <if_sid>60106</if_sid>
    <field name="win.system.eventID">^4624$</field>
    <field name="win.eventdata.logonType">^3$</field>
    <field name="win.eventdata.authenticationPackageName">^NTLM$</field>
    <description>Possible Pass-the-Hash - Network logon with NTLM</description>
    <mitre>
      <id>T1550.002</id>
    </mitre>
  </rule>
</group>
